# 触发回归集（evals）

用途：改 frontmatter description 后跑回归。每条在目标 harness 跑 3 次，正例触发率应 >0.5，负例不应触发。60/40 切分 train/validation，只按 validation 选 description。

## 正例（应触发）

1. 帮我把这个需求翻译成 prompt：我想做个每天备份数据库的东西
2. 整理成 prompt：自动检查网站存活，挂了通知我
3. 这个需求我怎么说清楚？就是做一个定时发周报的工具
4. 帮我写个提示词，给 Claude 用的，做数据清洗的
5. 帮我整理成给 Cursor 的任务：加个登录功能
6. 我不知道怎么跟 AI 描述这个：抓取网页然后存成表格
7. 想先把需求说清楚：做个客服机器人
8. 帮我把这个想法写成给 AI 的指令
9. 帮我理一下这个需求：监控 CPU 过高报警
10. 我口语太乱，帮我转成 prompt：检查文件重复然后删除

## 负例（近义误触发，不应触发）

1. 帮我把这段英文翻译成中文
2. 帮我直接改这个 bug，登录页报错
3. 帮我总结这篇文章
4. 解释一下什么是 prompt
5. 帮我把这段代码改成 TypeScript
6. 帮我写个周报
7. 帮我修一下服务器，CPU 占用 100%
8. 翻译成英文：今天天气不错
9. 帮我润色这段话，发朋友圈用
10. 直接帮我做：建一个 Django 项目

## 输出断言（output_cases，非触发类）

- 整条回复只有一个代码块，块外零字符
- 数字/区间/路径/版本号与用户原话逐字一致
- 不出现用户没提过的技术栈、文件名、接口
- 待确认 ≤1 行；每条验收可写成「给定…当…则…」
